# PoCI v0.1 Canonicalization and Evidence Hashing

Status: Draft normative profile  
Profile: `proofpath.poci.v0.1`

## 1. Goal

Independent implementations must compute identical bytes and digests for the same Action Proof Envelope. Canonicalization therefore forms part of the security boundary.

## 2. Canonical JSON profile

PoCI v0.1 uses the following restricted JSON canonicalization rules:

1. Input MUST be valid UTF-8 JSON.
2. Objects MUST be serialized with keys sorted by Unicode code point.
3. No insignificant whitespace is emitted.
4. Strings use JSON escaping and MUST be valid Unicode scalar values.
5. Numbers MUST be integers. Floating-point values are forbidden in security-critical fields.
6. Timestamps MUST use RFC 3339 UTC form `YYYY-MM-DDTHH:MM:SSZ`.
7. Duplicate object keys MUST be rejected before canonicalization.
8. The `extensions` object is included in the envelope root unless a future profile explicitly excludes a namespaced extension.
9. The field `evidence_integrity.envelope_root` MUST be replaced with `null` while computing the envelope root.
10. Signature bytes stored outside the envelope are represented by content-addressed artifact references, not embedded opaque binary data.

A reference implementation may use RFC 8785-compatible JSON Canonicalization Scheme behavior where it does not conflict with the restrictions above.

## 3. Digest format

All v0.1 digests use SHA-256 and lowercase hexadecimal:

```text
sha256:<64 lowercase hex characters>
```

Implementations MUST reject uppercase, truncated, or algorithm-ambiguous digests.

## 4. Domain separation

Every digest is computed over:

```text
ASCII("proofpath:poci:v0.1:<object-type>\n") || canonical_json_bytes
```

Defined object types:

- `intent`
- `authority`
- `causal-context`
- `proposal`
- `execution`
- `observed-result`
- `witness-statement`
- `verification`
- `envelope`

A digest for one object type MUST NOT be accepted as a digest for another object type.

## 5. Envelope-root algorithm

1. Parse JSON and reject duplicates or unsupported values.
2. Validate the Action Proof Envelope schema.
3. Copy the full envelope.
4. Set `evidence_integrity.envelope_root` to `null`.
5. Canonicalize the copied envelope.
6. Prefix the bytes with `proofpath:poci:v0.1:envelope\n`.
7. Compute SHA-256.
8. Encode as `sha256:<hex>`.
9. Compare in constant time where practical with the declared root.

Pseudocode:

```python
normalized = deep_copy(envelope)
normalized["evidence_integrity"]["envelope_root"] = None
payload = b"proofpath:poci:v0.1:envelope\n" + canonical_json(normalized)
root = "sha256:" + sha256(payload).hexdigest()
```

## 6. Artifact commitments

External artifacts MUST be referenced by:

- stable artifact identifier;
- media type;
- byte length when known;
- SHA-256 digest;
- role in the evidence chain.

A verifier MUST NOT fetch network artifacts by default. Offline verification relies on artifacts included in the portable evidence bundle.

## 7. Mutation behavior

Changing any of these values MUST change the envelope root:

- principal, agent, executor, observer, or witness identifier;
- intent validity window or replay identifier;
- authority scope or budget;
- causal parent;
- proposal parameters;
- execution receipt digest;
- observed result digest;
- witness verdict or reason code;
- verification decision;
- artifact digest.

Object key reordering and insignificant source whitespace MUST NOT change the root.

## 8. Verification output normalization

Normalized verifier output MUST contain keys in this logical order before canonical sorting:

- `profile_id`
- `envelope_id`
- `decision`
- `primary_reason_code`
- `reason_codes`
- `findings`
- `computed_envelope_root`
- `declared_envelope_root`
- `valid`

Arrays whose order is not semantically meaningful MUST be sorted by a documented stable key. Reason codes MUST be sorted lexicographically after the primary reason code is selected.

## 9. Golden vectors

PR #1 supplies the first valid envelope example. Issue #183 is complete when a reference canonicalizer records:

- canonical bytes;
- expected section digests;
- expected envelope root;
- at least one one-byte mutation vector;
- a key-reordered source vector with the same root.

Until golden values are generated by the reference implementation, the example MAY use `null` for `envelope_root`; a conforming verifier MUST treat `null` as “root not yet asserted,” never as a valid digest.
